# @dsh-external/dsh-file-drop

An optional browser provider owns `ctx.fileDrop`. The Host entry is inert; the Bundle makes the browser entry available. The public `types` and `client` exports expose `IFileDrop`, `FileDropRegion` and `FileDropHoverState`, including Cordis `Context.fileDrop` declaration merging. Version 0.1.0 has no upload, filesystem, Session or Remote API and requires no manager, sidebar, user-files provider or attachment UI.

`registerRegion({ element, canAccept, onHover, onDrop, onError? })` returns an idempotent disposer. `element` belongs to the router's document and may be registered once. Routing skips disconnected elements and chooses the first registered element in the event's composed path, so the deepest target receives the gesture. A refusing child blocks its parent. Acceptance is re-read for each native drag event and immediately before intake. `onHover({ active, accepted })` identifies the active target; inactive notifications carry both values as false. `onDrop(files)` receives one captured array of browser `File` objects and may return a Promise.

Only data transfers containing the native `Files` type enter this router. It prevents browser file navigation across the document, including outside targets, but shows no overlay and admits no files outside a region. Text and internal-tab drags retain native behavior. Drag exit, drag end, window blur, region removal and provider disposal clear hover. Disposal removes all listeners; uploads already handed to consumers retain their consumer-owned lifetime. Callback exceptions and Promise rejections reach `onError`, or the browser console when it is absent; an error handler's own failure is reported to the console.

Consumers own overlays, SVGs, acceptance rules, error presentation and intake. A manager can watch for the optional service with `ctx.inject(['fileDrop'], ...)`, register its mounted target groups when it arrives, and dispose registrations when it leaves. That optional watcher must not block manager activation or add a mandatory provider Bundle.

The included Chat adapter waits for `conversation.input.fileDrop` without requiring that seat or the attachment renderer. InputBar supplies its region id, current image-admission flag, localized title/limits and validated image callback. The adapter binds the region and renders the Chat illustration inside it with pointer-inert styling. Conversation retains image-format/count/size validation and draft ownership; the attachment renderer retains the rail and previews. An absent `dropRegionId` leaves the adapter inert; a supplied missing element is an explicit integration error.

The [installation map](../../.intent/state/STATE.md) owns profile operations and Host patch attribution. Build outputs include `lib/index.js`, `lib/client.js` and declarations under `lib/types`. The Client uses the Harness's preloaded React/Cordis identities and owns its stylesheet through a Cordis effect. This plugin creates no model input or provider request and has no independent token or KV-cache effect.
